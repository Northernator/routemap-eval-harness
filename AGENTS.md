# RouteMap Evaluation Harness Agent Notes

## Project goal

Make this harness a runnable local evaluation project for comparing RouteMap retrieval against simple keyword retrieval, optional neural embedding retrieval, and optional LLM route extraction.

## Coding conventions

- Keep the default demo fully local and deterministic; it must not require external APIs.
- Keep optional integrations isolated in their own scripts and document extra dependencies separately.
- Prefer small CSV fixtures under `data/gold/` for sample evaluation inputs.
- Write generated demo outputs under `data/outputs/`.
- Preserve the script-per-task layout in `src/`; avoid broad framework rewrites.
- Use standard-library Python where practical. Keep required dependencies minimal and explicit.
- When adding CLI behavior, keep arguments explicit and compatible with existing scripts.
- Favor readable metrics CSVs over hidden state or notebook-only workflows.

## RouteMap Harness (v0.1) — invariants for agents

The harness (`src/routemap_harness/`) is the external reliability layer: `AI -> classify -> validate -> repair -> escalate -> audit`. Treat these as hard rules. See `HARNESS_V0_1_BUILD_PLAN.md` for the full design and the prompt-by-prompt build history.

- **Wrap, don't rebuild.** The harness composes the existing packages — it calls `routemap_controller.route_decide()` and `routemap_validators.check_output()`. Never copy or re-implement routing, classification, or checker logic into `routemap_harness`. If a lane is wrong, fix it in its owning package.
- **Verdicts are one-sided. Never invent a verdict that asserts correctness.** A `verdict` is only `RULED_OUT_WRONG`, `NOT_RULED_OUT`, or `UNCHECKABLE` (from `dr_verifier_v1` / `routemap_validators.verdicts`). `accept | repair | retry | escalate | reject | full_compute` are *actions* (policy, decided in `policy.py`); `accepted | rejected | escalated | repaired | failed` are *final_status*. Keep the three concepts in separate fields. A checker may never emit "accept".
- **Never execute model output.** The Python-code lane is `ast.parse` only. No `exec`, `eval`, `compile`-and-run, or `import` of model-produced strings, ever.
- **Writers target ignored paths only.** All generated artifacts (audit JSONL, demo output, evidence) go under `data/outputs/`, `data/runs/`, or `EVIDENCE/` — all gitignored. Never write generated files into a tracked dir (`examples/`, `data/harness_gold/`, `data/v1/`, `src/`). The default audit path is `data/outputs/audit.jsonl`; tests write to `tmp_path`. (A stale `data/v1/.../slice_07/example_audit.jsonl` was the one historical leak — fixed.)
- **Frozen sets are verified, never regenerated by the runner.** Locked sets (`data/harness_gold/` with `SHA256SUMS`, `data/blind/` with `manifest.json`) are checksum-locked; their tests verify the manifest and refuse to run on any change. `run_evidence.py` only *reads/scores* them. Any generator is a separate, manual, one-off step — the runner must never rewrite a frozen set or its checksum.
- **Reuse the existing exact-compute path.** Arithmetic escalation computes the exact answer via `routemap_digital.parse_expression()` -> `routemap_bench.tasks.exact_value_feasible()` / `compute_ground_truth()`. Never `eval()` an expression.
- **Core stays offline and deterministic.** numpy + stdlib only on the check path; zero network calls. All model I/O sits behind the `model_fn` adapter contract (`adapters.py`). Isolate extra deps in their own file (`requirements-api.txt` for the FastAPI service); the API handlers call core functions and contain no logic.
- **Audit is canonical and schema-locked.** Every emitted record validates against `schemas/harness_decision_v1.schema.json` (100% schema-valid) and embeds the lane record under `validator_record`. No silent prune: every accept/repair/prune names the validator/guard or an explicit `escalation_target`.
- **Zero false accepts is a test, not a claim.** Changes that touch any lane must keep `tests/test_harness_gold.py` green (`false_accepts == 0`, sound-lane FP `0.000`). Every new behavior ships a pytest test, a one-line `EVIDENCE_PACK.md` note, and (for durable checks) a `run_evidence.py` step.
- **Run from repo root** (`routemap_eval_harness/routemap_eval_harness/`, the dir with `.git`) using `PYTHONPATH=src`, Python 3.11. Primary CLI surface is `python -m routemap_harness`. Note: this is a Windows/PowerShell environment — `grep` is unavailable; use `git` pathspecs or native scans.

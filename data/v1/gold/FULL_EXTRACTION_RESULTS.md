# Full Extraction Results

## Dataset

- Input seed annotation: `data/v1/gold/v1_annotation_targets_clean.csv`
- First-pass full gold: `data/v1/gold/v1_full_extraction_gold_v1.csv`
- First-pass prediction: `data/v1/gold/v1_full_extraction_pred_v1.csv`
- Dataset size: 99 rows

This is a first-pass deterministic extraction benchmark. The gold extension fills `gold_entities`, `gold_operative_status`, `gold_relation`, and `gold_answer_relevant` with transparent heuristics. The prediction file uses frozen `classify_role_v3` for `pred_role` and derives the remaining prediction fields from the predicted role plus the same deterministic entity/rule helpers.

## Entity Overlap

- Exact entity-set match: 1.000
- Average Jaccard overlap: 1.000
- Rows with zero entity overlap: 0

Entity scores are high because this first benchmark uses the same deterministic entity extractor for the first-pass gold fill and prediction. Treat this as a pipeline sanity check, not evidence that entity extraction is solved.

## Limitations

- The gold file is first-pass heuristic gold, not adjudicated human gold.
- Prediction role quality is bounded by frozen `classify_role_v3`; no v3 tuning was performed here.
- Entity evaluation is inflated because gold and prediction share the same extractor.
- Relation and operative-status scores largely track role errors because the first-pass rules derive those fields from role.
- The seed text still contains route headings, while the current v3 classifier was developed around no-leak semantic evaluation.

## Next Improvement

The next useful step is to create a manually reviewed full-extraction subset where entities, operative status, relation, and answer relevance are adjudicated independently. After that, split entity extraction into its own prediction heuristic so entity overlap is no longer guaranteed by shared generation rules.

The v2 result is correct for the structured seed dataset because explicit headings such as `### EXAMPLE`, `### NEXT_STEP`, and `### RESULT` are part of that annotation signal. It should not be interpreted as semantic generalisation. The no-leak and held-out role evaluations remain the better tests of whether the classifier understands unseen role semantics without heading leakage.

The v2 no-leak score remains perfect on the seed-derived full-extraction file.
